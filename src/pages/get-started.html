01 · Install

Pick where you want to work.

In VS Code

Install AgenticFlowX, then open it from the activity bar (Cmd/Ctrl + Alt + A). AgenticFlowX: Open Workbench opens the project panels.

VS Code Marketplace ↗Open VSX ↗

In the agent you already use

Install the Claude Code plugin, or run afx-cli to add the skills for Claude Code, Codex, or Copilot. The workflow runs without the extension. 

/plugin marketplace add AgenticFlowX/afx
/plugin install afx@afx

All install options, including the CLI →

The extension bundles the Pi SDK and the core workflow skills. You don't need to install Pi separately unless you want to use your own Pi CLI.

02 · Connect a model

Bring the access you already have.

  1. Open Settings → Models. Sign in with a supported subscription, add an API key, or point a preset at a local server.
  2. Pick a model in chat. The picker groups models by configured provider. Thinking levels and image input follow the selected model.
  3. Already use Pi? In Settings → Runtimes, detect your Pi CLI and turn on Pi RPC to use its own catalog and sign-in.

Which models you see depends on the active runtime, the provider, and your account. Keys you enter are stored in VS Code SecretStorage.

03 · First chat

Ask before you change anything.

Chat has three modes. Switch with Cmd/Ctrl + Shift + M; the status bar shows the current one.

Code

Edits, implementation, debugging, and commands. Full access.

Explore

Read-only investigation, enforced by the extension. Ask where behaviour lives.

Spec

Planning first: clarify requirements, review the design, and turn it into tasks.

Try this in Explore

“How does project search work today? Show me the relevant files and the gaps in its tests.”

Type / for AFX skills and commands, @ to mention a file, and ! to run a shell command. Commands that look destructive are flagged before they run.

04 · First Dash or spec

Write down the change before the agent makes it.

Dash

A known-scope fix or refactor. Purpose and tasks in one file. Try /afx-dash.

Sprint

A focused feature. Spec, design, and tasks in one file, approved in stages. Try /afx-sprint.

Full spec

Auth, migrations, public APIs, cross-team work. Four files. Start with AgenticFlowX: New SDD or /afx-scaffold.

Review the proposed scope before implementation. If a Dash outgrows itself, AFX says so; moving up keeps your IDs and links. Follow the first-feature walkthrough →

05 · Open the Previewer

Read the plan as a document, then act on it.

Open any spec Markdown file and choose AgenticFlowX: Open Preview from the editor title bar. Each document type gets its own actions. A spec offers Refine, Author, Validate, Review, and Approve. Actions that create content draft a command in chat for you to review; checks and approvals, such as Validate, Review, and Approve, run straight away.

06 · Verify

Check the work, then sign it off.

  1. Run the task check. From a tasks document, choose Verify, or run /afx-task verify. It checks files, @see links, and leftover TODOs against the spec.
  2. Trace the links. /afx-check trace or AgenticFlowX: Verify Traceability looks for broken or missing references.
  3. Test and review it yourself. These are text checks; they don't run your code. Run your tests, then tick the human sign-off after the agent's.

Skills & trust

Know where every skill comes from.

Settings → Support shows loaded commands, their source paths, and scope. Core skills are bundled; personal and team skills are discovered from standard SKILL.md folders.

Scope Locations
Global ~/.pi/agent/skills or $PI_CODING_AGENT_DIR/skills; ~/.agents/skills
Project .pi/skills and .agents/skills
Custom afx.skills.extraPaths accepts absolute, home-relative, and workspace-relative paths.

Names and descriptions load first; full instructions load when needed. Project-local Pi settings, skills, extensions, and packages follow afx.pi.projectTrust: ask, trust, or ignore. Exclude individual tools with afx.pi.excludedTools.

Settings & privacy

Make the workspace yours.

Settings covers Models, Runtimes, Skills, and appearance. About shows the bundled skill version. The Meridian theme comes in seven styles: lyra, luma, maia, nova, vega, mira, and sera.

Keep useful history

Search, reopen, rename, or export a session. Copy a recap for the next agent or your next day of work.

Choose your panels

Hide unused Workbench tabs with afx.experimental.workbenchHiddenViews. Turn on the experimental Canvas with afx.experimental.canvas.

What leaves your machine

  • Your prompts and context go to the model provider you choose. With a local runtime, they go to the endpoint you configure.
  • Your documents stay as Markdown files in your repository. There is no AgenticFlowX account or backend.
  • UI analytics (Microsoft Clarity in the extension's panels) are on by default. They respect VS Code's telemetry setting and Do Not Track, and you can turn them off with afx.telemetry.enabled.
Context, logging, and network settings

afx.context.includeActiveFileContext controls active-file context. afx.logLevel sets output verbosity; afx.debugPerf adds streaming diagnostics. afx.network.httpProxy routes requests through a proxy. afx.chat.autoOpenModifiedFiles opens files the agent changes.

Troubleshooting & FAQ

Practical answers.

Do I need an AgenticFlowX account?

No. AgenticFlowX is open source. Connect your own model account, API provider, or local runtime; provider usage and limits are separate.

A model doesn't appear, or a request fails.

Check which runtime is active first. The bundled SDK uses Settings → Models; Pi RPC uses Pi's own sign-in and catalog. Then confirm your sign-in or key, endpoint, and model ID. For slow local startup, raise afx.runtime.responseStartTimeoutMs.

Open model setup →
The agent stops responding.

Run AgenticFlowX: Agent Smoke Test to check the runtime, then AgenticFlowX: Restart Agent Process. AgenticFlowX: Show Logs opens the output panel for details.

A skill I expected isn't listed.

Open Settings → Support to see where skills load from. Project-local skills follow afx.pi.projectTrust; if it's set to ignore, they won't load. Add extra folders with afx.skills.extraPaths.

Where are the documents?

Specs, designs, tasks, and journals are Markdown in your workspace, usually under docs/specs/. Workbench notes and the board live under .afx/; Canvas uses .afx/project.canvas.

Can I try a complete example?
