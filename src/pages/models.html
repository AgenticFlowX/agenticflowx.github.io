The Pi foundation

One harness, two ways to run it.

AgenticFlowX builds the editor, document workflow, and Workbench around Pi. Both runtimes run the same conversation workflow; each owns its own model configuration.

Default

Bundled Pi SDK

Runs inside the extension, on by default (afx.sdk.enabled). Configure providers in Settings → Models. No separate Pi install.

Optional

Pi CLI over RPC

Runs your installed Pi as a subprocess, off by default (afx.rpc.enabled). Reuses Pi's model catalog, sign-in, sessions, and skills.

If a model is missing, check which runtime is active before changing credentials: SDK providers and Pi providers are configured in different places.

03 · Local & custom

Run on your hardware

Presets for Ollama, LM Studio, and vLLM. Anything else that speaks an OpenAI-compatible API, such as llama.cpp's server, through the Custom option.

Sign-in support doesn't guarantee a particular plan or model. Which models you can use depends on the runtime, the provider, and your account; provider limits and charges still apply. The model picker shows what your current setup exposes.

Connect a provider

Three recipes cover most setups.

Subscription sign-in

  1. In Settings → Models, choose the provider and select Sign in.
  2. Complete its browser or device-code flow.
  3. Return to the model picker and choose an available model.

API key

Select the provider, add its key, and choose a model. Keys you enter are stored in VS Code SecretStorage. Supported environment variables can also supply keys.

Gateways and enterprise providers

OpenRouter, Vercel AI Gateway, Cloudflare AI Gateway and Workers AI, Amazon Bedrock, Azure OpenAI, and Google Vertex have catalog entries. Fill in the provider's required authentication and endpoint fields.

Run local models

Keep inference on your own machine.

Start your model server, load a model that supports the tools your task needs, then point AgenticFlowX at its endpoint.

Ollama

Choose the Ollama preset and point it at your running server, usually http://localhost:11434. You can also set afx.sdk.ollamaBaseUrl.

LM Studio, vLLM, and llama.cpp

LM Studio and vLLM have presets. For llama.cpp's server or any other OpenAI-compatible server, use Custom with the OpenAI completions format. Enter the actual base URL and model ID, and a key if your server needs one.

Requests go only to the endpoint you configure. Image input, tool use, reasoning, and speed depend on the model and the server.

Use your Pi CLI

Keep the Pi setup you already have.

  1. Open Settings → Runtimes and run AgenticFlowX: Auto-detect Pi CLI Binary, or set afx.agentBinaryPath.
  2. Turn on Pi RPC with afx.rpc.enabled. Sign in to providers with Pi's /login.
  3. Choose from Pi's model catalog. RPC custom providers come from Pi's models.json, not the SDK settings.

Pi configuration lives in ~/.pi/agent or $PI_CODING_AGENT_DIR. Project-local resources still follow afx.pi.projectTrust.

Custom endpoints

Configure any endpoint explicitly.

SDK custom providers speak four formats: OpenAI completions, OpenAI responses, Anthropic messages, and Google Generative AI. Presets cover Ollama, LM Studio, vLLM, OpenRouter, Vercel AI Gateway, Moonshot (Kimi), an Anthropic proxy, and Google AI Studio; Custom covers the rest. Set the format, base URL, authentication, and model capabilities to match your endpoint.

SDK custom providers are managed by AgenticFlowX. RPC custom providers belong in Pi's configuration.
